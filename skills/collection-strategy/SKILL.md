# Collection Strategy

## Purpose

Create a balanced template portfolio with clear buyers, jobs-to-be-done, page inventories, visual theses, and reasons to purchase.

## Inputs

- Base-template audit.
- User constraints.
- Target marketplace requirements, when named.
- Current collection goals and technical capabilities.

## Procedure

1. Generate 8–12 viable template concepts across different industries, content models, and layout densities.
2. Reject concepts that require a backend to appear complete unless a static demonstration mode is credible.
3. Score each concept from 1–5 for buyer clarity, marketplace breadth, visual differentiation, Astro suitability, demo-content quality, implementation risk, and bundle complementarity.
4. Select five concepts with distinct buyers and at least one admin/dashboard product.
5. Assign each concept a product name, one-sentence promise, buyer, job-to-be-done, required pages, optional pages, signature sections, interaction scope, data/content model, art direction, and customization story.
6. Define explicit anti-overlap rules for every concept: layouts, components, patterns, and visual tropes it must not borrow from another collection member.
7. Create a portfolio narrative explaining why the five products belong in one collection.

## Required output

- `docs/collection-strategy.md`
- Five files in `docs/template-briefs/`
- Initial entries in `docs/route-matrix.md`
- Initial entries in `docs/differentiation-matrix.md`

## Brief acceptance criteria

Each brief must enable implementation without inventing the product during coding. It must include at least five routes unless the product's market convention strongly supports fewer, and it must identify one unmistakable signature composition.
