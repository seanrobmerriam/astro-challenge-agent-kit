# Template Production Workflow

## Outcome

One complete, tested, documented, and package-ready Astro template produced from an approved brief.

## Repeat this workflow for each template

### 1. Initialize

Create the app from a fresh base-template derivation. Apply package metadata, expression-mode tokens, global foundations, and app shell. Verify a baseline build.

### 2. Create content architecture

Define data structures and realistic sample content. Separate buyer-editable content from component code where useful. Record image requirements and licensing status before sourcing assets.

### 3. Implement the signature route

Build the route that best proves the product's market position. Complete its desktop and mobile composition, states, metadata, and content before expanding the component set.

Checkpoint: compare it against all completed siblings. Correct visual convergence immediately.

### 4. Implement shared app-level patterns

Build navigation, footer or app shell, page header, repeated content modules, forms, cards, and domain-specific components. Keep high-level components inside the app.

### 5. Implement remaining routes

Build routes in risk order. Include edge states and long content. Verify internal links as each route lands.

### 6. Add deliberate interactions

Implement only interactions required by the product demonstration. Use native disclosure, dialog, form, and navigation behavior where appropriate. Hydrate the smallest possible island.

### 7. Responsive pass

Test at the defined viewport set. Resolve navigation, overflow, tables, grids, media, forms, and typography issues. Ensure the narrow layout is designed rather than collapsed.

### 8. Accessibility and content pass

Check semantics, heading order, keyboard behavior, focus, labels, errors, contrast, alternative text, reduced motion, copy consistency, and demo-data disclosure.

### 9. Performance and build pass

Run the app's checks and production build. Review assets, client JavaScript, console output, and route output. Remove unused code and dependencies.

### 10. Documentation pass

Write README, customization, content, deployment, license notices, changelog, and known limitations. Follow the documentation from a clean checkout.

### 11. Differentiation checkpoint

Score the new app against every completed sibling. Remediate failing pairs before starting another template.

### 12. Package candidate

Create a release candidate archive and verify it in a clean directory. Final marketplace packaging occurs after collection-wide QA.

## Exit criteria

- All intended routes complete.
- Build passes.
- QA issues have severity and disposition.
- Buyer documentation works.
- Pairwise differentiation passes.
- No unresolved asset-license issue.
